# 《V2.1 离线辩论引擎 · 开发指令》

> 这份指令用于交给任何一个编程 AI（Claude / Cursor / 本 agent 自身 / 其它）去**重构**现有的 `godot_logic_game` Godot 项目，把它从"一句话→查关键词→返回一个谬误"，升级为"玩家与一个**完全离线的规则型辩手**进行多回合论证攻防"。
>
> 项目定位：**纯离线、纯规则引擎、零 AI 模型、零网络**。目标运行环境：**Godot 4.7.2 stable（手机端、桌面通用）**。

## 0. 给执行者的总纲（先读）

### 0.1 一句话定位
把 `Main.gd` + `DebateEngine.gd` + `KnowledgeBase.gd` 三个文件，重构成一套**数据驱动、模块化、可扩展**的多文件离线博弈系统。逻辑全部用 **String / Array / Dictionary / RegEx / 本地数据库 / 状态机 / 权重 / 随机数** 实现，**不引入任何 AI 模型、不联网、不请求任何网络权限**。

### 0.2 硬约束（违反即失败）
1. **不得联网**：禁止任何 `HTTPRequest`、`OS.execute` 拉起 curl/wget、`StreamPeerTCP`/`StreamPeerTLS`、`TCP_Server`；工程内不得出现 `http://`、`https://` 作为运行逻辑；`project.godot` 不得申请网络权限。
2. **不得引入外部 AI**：不允许 Ollama、llama.cpp、OpenAI、本地 HTTP 推理、`FileAccess` 读取外部模型仓库等。
3. **不许虚构 Godot 4.7.x API**：只用**已验证存在**的 API。本指令第 5 节给出"安全 API 清单"，只允许这些及它们的合法成员。
4. **只改指定文件、只新增指定文件**：见第 2.2 节文件树。不得顺手改动与任务无关文件，不得删除 `逻辑与辩论资料库/` 下任何资料。
5. **中文为主，英文修辞术语保留**（如 *Ad Hominem*、*Slippery Slope*、*Presupposition*）。
6. **不谈版权原文**：所有来自《逻辑与辩论资料库》的素材必须**改写/摘要**，不得整段照抄。
7. **不破坏现有可用功能**：气泡界面、话题、计分、导出、结算、情绪处理、防刷屏、圆角修复、气泡宽度修复，必须保留（见第 7 节"已实现清单"，**迁移时保留，不要重写坏**）。
8. 每一步都以"当前版本仍然可打开、可运行"为底线，做到**增量可验收、可回滚**。

### 0.3 交付目标
- 代码通过 `gdparse`（语法树）与 `gdlint`（仅风格项可容忍）静态校验。
- 逻辑通过"Python 移植仿真"验证：任何输入都不输出空文本，情绪/垃圾输入走安抚分支，正常论证走谬误/攻击分支。
- 生成可导入的 `godot_logic_game_import.zip`（含全部 `.gd` / `.tscn` / `project.godot`）。

### 2.1 整体流程（DebateEngine 编排）
```

   ↓

   ↓

   ↓
ARGUMENT_ANALYSIS      # 转成结构化 argument dict
   ↓

   ↓
PLAYER_ARGUMENT_UPDATE # 更新玩家论证生命值/完整度
   ↓
AI_ATTACK_CANDIDATES   # 生成最多 3 个攻击候选
   ↓
ATTACK_SCORING         # 攻击价值评分
   ↓
AI_DECISION            # 选出最高分攻击
   ↓
RESPONSE_GENERATOR     # 组装自然语言回应（含表情）
   ↓
AI_RESPONSE            # 渲染
   ↓
PLAYER_REBUTTAL        # （下一步）玩家反击
   ↓
REBUTTAL_ANALYSIS      # 五级反击评估
   ↓
AI_ARGUMENT_ANALYSIS
   ↓
CONCESSION_CHECK       # 判断是否让步（承认→保留→转移）
   ↓
SCORE_UPDATE
   ↓
ROUND_UPDATE
   ↓
WIN_CONDITION_CHECK
   ↓
NEXT_ROUND / SETTLEMENT
```

## 3. 各模块职责与接口（务必照此实现）

### 3.1 `DebateStateMachine.gd`（回合阶段状态机）
状态机，枚举回合阶段：
```
enum Stage { OPENING, ARGUMENT, COUNTER, CROSS_EXAM, FINAL }
enum Phase  { AI_TURN, PLAYER_TURN, SETTLE }
```
- 维护 `current_stage`、`round_in_stage`、`total_rounds`。
- 提供 `advance()`、`current_stage()`、`is_final()`。
- 标准一局：OPENING 1 回合 → ARGUMENT 3 → COUNTER 3 → CROSS_EXAM 2 → FINAL 1（共 10 个主要回合）。允许玩家一句内多轮，不强制一字一句。

### 3.2 `KeywordExtractor.gd`
- `extract(text: String) -> Dictionary`，返回 `{ causal:[], opinion:[], evidence:[], examples:[], contrast:[], compare:[], absolute:[], quantifier:[], emotion:[], authority:[], action:[], question:bool }`。
- 关键词库放在 `data/KeywordDatabase.gd`，12 类 + 动作词（见第 4.1 节）。

### 3.3 `ArgumentAnalyzer.gd`（核心，只做结构，不说话）
`analyze(text: String) -> Dictionary`，输出**统一 schema**（原样保留，勿改字段名）：
```gdscript
{
    "text": "",                # 原文
    "claim": "",               # 结论/主张
    "premises": [],            # 前提（陈述）
    "evidence": [],            # 证据/数据/来源
    "examples": [],            # 例子
    "questions": [],           # 问题
    "conditions": [],          # 条件/限定（“在某些情况下…”）
    "conclusions": [],         # 由“所以/因此/因而/由此可见…”引出的结论句
    "connectors": [],          # 连接词（因为/所以/但是/然而…）
    "quantifiers": [],         # 量词（很多/所有/部分/大多数…）
    "emotion_signals": [],     # 情绪词
    "authority_signals": [],   # 权威词
    "causal_signals": [],      # 因果词
    "comparison_signals": [],  # 比较词
    "certainty": 0.0           # 0.0~1.0：强度（受限定词/概率词影响）
}
```
- 由 `KeywordExtractor` 的产出 + `RegEx` 切分句子，填充该 dict。
- **论证关系**：把文本拆成 `PREMISE → INFERENCE → CONCLUSION`。例："酒驾会增加事故风险，因此应该加强处罚" → P1=酒驾增加事故风险、P2=降低事故需要减少酒驾(隐藏前提)、C=应该加强处罚。

### 3.4 `FallacyDetector.gd`
- `detect(argument: Dictionary) -> Array[Dictionary]`，返回命中项（可多个），每项 `{ name, en, confidence, explain, probe, reductio, counter }`。
- 数据源 `data/Fallacies.gd`，每条比 V1 多一个 `counter` 字段（标准答复/反例）。
- **置信度不是非黑即白**：
  - 绝对化词（所有/任何/从来/永远/一定/必然/绝对/完全/根本/都/没有例外）→ 提高"过度概括/绝对化/滑坡/假两难"置信度。
  - 概率/限定词（可能/大概/通常/一般/多数/部分/有时/往往/倾向于/在某些情况下）→ 降低"过度概括"置信度。
  - **诉诸权威**：出现"专家/教授/科学家/医生/老师/权威/官方/政府/名人/冠军/诺贝尔/研究机构"仅 +低置信度；必须**同时**出现"专家说 X / 所以 X 一定正确"式的"权威+因果+绝对化"组合，才显著加分。
- 命中优先顺序：情绪化（由引擎先处理）→ 可信度最高的谬误。

### 3.5 `AICombatDecision.gd`
- `decide(argument) -> Array[Dictionary]`：生成**最多 3 个攻击候选**，每个含 `{ type, target, attack_score, text_hint }`。
- 攻击类型枚举：
```
ATTACK_CLAIM        攻击结论
ATTACK_PREMISE      攻击前提
ATTACK_EVIDENCE     攻击证据
ATTACK_CAUSALITY    攻击因果
ATTACK_DEFINITION   攻击定义
ATTACK_SCOPE        攻击范围
ATTACK_EXCEPTION    寻找例外
ATTACK_COUNTEREXAMPLE 寻找反例
ATTACK_CONTRADICTION  寻找自相矛盾
ATTACK_REDUCTIO     归谬
ATTACK_RELEVANCE    攻击相关性
```
- **攻击评分公式**：
```
攻击价值 =
  漏洞明显度 × 0.30
+ 与结论相关度 × 0.25
+ 证据缺口     × 0.20
+ 反击难度     × 0.15
+ 当前回合策略 × 0.10
```
- 选最高分攻击。**没有明显谬误也要能攻击**：证据不足 / 定义不清 / 因果关系缺失 / 方案有效性未知 / 成本未考虑 / 存在反例 / 结论范围过大。

### 3.6 `ResponseGenerator.gd`
- `generate(reply_parts: Dictionary, difficulty: Dictionary) -> String`：把 `{opening, attack, counterhint, concession, emoji}` 组装成自然语言，附 emoji（按已实现的 `KnowledgeBase.emoji(scene)`）。
- 输出结构：`【我注意到】… / 【为什么】… / 【攻击点】… / 【让步】…`，让步见第 4.5 节。

### 3.7 `RebuttalAnalyzer.gd`
- `analyze(player_input, ai_attack) -> Dictionary`，返回 `{ rebuttal_type, target, quality, text }`。
- **反击五级**：`0=无效 / 1=弱 / 2=部分有效 / 3=有效 / 4=致命`。
  - 0 → "你才是错的。"
  - 1 → "我不同意。"
  - 2 → "也许还有其他情况。"
  - 3 → "你的结论依赖这个前提，但你没证明它成立。"
  - 4 → "你的攻击针对我的表达方式，而非实际论证，因此即使成立也无法推出我错。"
- 例：AI 说"你是诉诸大众"，玩家回"我没因多数人支持就认为它正确，只是把社会接受度当作政策可行性的一个证据" → `{ rebuttal_type: 区分概念, target: 诉诸大众, quality: 0.91 }`。效果：AI 攻击强度 −30%，玩家逻辑分 +3。

### 3.8 `ScoreSystem.gd`
- 隐藏"论证生命值/完整度"：
```
player_argument_integrity = 100
ai_argument_integrity     = 100
被有效攻击     -5 ~ -20
致命攻击       -25 ~ -40
有效反击       +5 ~ +15   # 设回血上限，比如每局最多 +30
```
- 维护：玩家总分 / AI 总分 / 命中谬误数 / 讲理次数 / 成功反击 / 各自让步次数。

### 3.9 `SettlementSystem.gd`
- **胜负判定**：
```
player_total = 玩家总分 + 玩家论证完整度 + 成功反击 + AI让步 - 玩家逻辑漏洞
ai_total     = AI总分  + AI论证完整度   + 成功攻击 + 玩家让步 - AI漏洞
差值 >= 20   明显胜利
10 ~ 19      小胜
-9 ~ 9       平局
-10 ~ -19    小败
<= -20       明显失败
```
- **允许双输**：若双方"论证完整度"都低于阈值（如 <40）→ 判定"逻辑平局 / 双方论证均未成立"，避免强行判一方输。例："所有人都应支持" vs "专家说不好" vs "专家都说了所以你错" → 双方论证不足 → 平局。
- **动态提前结束**：当一方"核心论证强度"从 100 跌到 <20 时，进入 FINAL 陈词（可提前结算）。

### 3.10 `ExportManager.gd`
- 把现有 `_on_export` 迁移过来：写 `user://辩论记录_*.md`。保留 `_strip_bbcode` 逻辑。

### 3.11 `DebateEngine.gd`（编排 + 唯一对外入口）
- 保留对外方法：`respond()` / `setup_topic()` / `settle()` / `hint()` / `reset()` / `ai_score()` / `user_score()` / `user_hits()` / `round_count()` / `max_rounds`。
- `respond()` 内部改为调用上表流程（第 2.1 节），但仍必须保证：**任何输入都不返回空文本**（已有兜底保留）。
- 持有 `state_machine`、`argument_analyzer`、`fallacy_detector`、`combat`、`response_gen`、`score`、`settlement` 等实例。

### 3.12 `Main.gd`（界面层）
- 只保留 UI：构建气泡/计分/辩题/结算/导出/求助/防刷屏；调用 `DebateEngine`。
- 可新增面板场景（`ScorePanel`/`TopicPanel`/`HelpPanel`/`SettlementPanel`/`ChatBubble`），把现有内联 UI 抽出。
- 气泡渲染已修复（宽度下限 + 中文换行），**保持不动**。

## 4. 数据与算法规格

### 4.1 关键词 12 类（数据放 `data/KeywordDatabase.gd`）
① 因果：因为、由于、导致、造成、产生、引起、因此、所以、结果、影响、原因、根源、决定、促成
② 观点/结论：我认为、我觉得、我的观点、我的立场、应该、不应该、必须、不能、可以、不可以、显然、毫无疑问、归根结底
③ 证据：数据显示、研究表明、调查显示、统计、实验、数据、案例、证据、事实、报告、论文、研究、调查、样本
④ 举例：例如、比如、举例、假设、假如、试想、现实中、历史上、某人、某国、某事件
⑤ 转折：但是、然而、不过、可是、虽然、尽管、反而、相反、实际上、事实上
⑥ 比较：比、更加、更重要、不如、类似、相似、不同、区别、相比、相较
⑦ 绝对化：所有、任何、人人、从来、永远、一定、必然、绝对、完全、根本、都、没有例外
⑧ 概率/限定：可能、大概、通常、一般、多数、部分、有时、往往、倾向于、在某些情况下
⑨ 情绪：愤怒、害怕、可怜、悲惨、可恨、恶心、羞耻、可耻、恐怖、惨、太过分
⑩ 权威：专家、教授、科学家、医生、老师、权威、官方、政府、名人、冠军、诺贝尔、研究机构
⑪ 动作关键词：意味着、说明、证明、表明、推出、得出、足以说明、可以看出、由此可见、换句话说、这告诉我们
⑫ 疑问词：为什么、凭什么、是否、难道、真的吗、吗、呢、何

> 注意：⑨/⑩ 只作**信号**，最终置信度需结合上下文（见 3.4 节）。

### 4.2 `ArgumentAnalyzer` 输出 schema
见 3.3 节 dict，字段名**不得改动**（其它模块依赖）。

### 4.3 攻击类型（11 种）
见 3.5 节枚举。

### 4.4 AI 三档难度（真正改变行为，不是摆设）
以 `{ attack_weight, concession_rate, reductio_rate, question_rate, error_rate }` 驱动：
```
温和     attack 0.5  concession 0.7  reductio 0.2  question 0.5  error 0.15   教学型
毒舌     attack 0.8  concession 0.35 reductio 0.55 question 0.75 error 0.08   压迫型
归谬狂魔 attack 1.0  concession 0.15 reductio 0.9  question 0.9  error 0.05   找极端后果/隐藏前提
```
- 难度只改这些权重，**核心逻辑不写死**。`DebateEngine` 暴露 `difficulty`（0/1/2）。

### 4.5 让步机制（重要自然感来源）
规则：`player_rebuttal >= 3` 时，AI 按 `concession_rate` 触发让步。
结构：**承认 → 保留 → 转移攻击点**。
- 承认："这一点我承认，你确实回应了我的主要质疑。"
- 保留："但这只能说明你的前提**有可能**成立，还不足以证明最终结论。"
- 转移："所以我把攻击点转到你的证据来源上。"
让步等级：
```
MINOR  承认一个细节        "这一点我承认。"
PARTIAL 承认一个前提        "你这个反例确实成立。"
MAJOR  承认核心攻击失败     "我的上一轮攻击不足以推翻你的结论。"
FULL   承认论证无法成立     "好，这一轮你赢了。"
```

### 4.6 回合阶段（一局默认 10 个主要回合）
OPENING 1 → ARGUMENT 3 → COUNTER 3 → CROSS_EXAM 2 → FINAL 1。

### 4.7 动态提前结束
一方"核心论证强度"降到 <20 时提前进入 FINAL 陈词并结算。

### 4.8 双输
双方论证完整度都 <40 → "逻辑平局 / 双方论证均未成立"。
